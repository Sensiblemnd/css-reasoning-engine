CSS engineering judgment, encoded as Agent Skills.

Three deterministic rule systems: css-engineer, css-reviewer, and css-refactor, that route into one shared knowledge base, so AI coding agents generate, audit, and modernize CSS the same way every time.

One knowledge base, three roles

Each skill is a lean core that resolves rules from the same shared references, so the rules can't drift between generating, reviewing, and refactoring.

Generate

css-engineer

Writes new modern native CSS: decision engine for layout, responsive, color, and animation choices, cascade layers, tokens, logical properties, web components, and a self-review checklist.

The layer contract

Every rule the skills generate lands in exactly one of these layers, declared once, in this order. The linter checks the order itself too: a misspelled layer name or a layer used before the order is declared would quietly change which styles win, so both are flagged.

  1. reset

    Contains
    Normalization, box-sizing, per-element margin resets
    Never
    Component styles, any * declaration except box-sizing

  2. tokens

    Contains
    :root custom properties, @property registrations, @font-face
    Never
    Selectors other than :root / ::backdrop

  3. base

    Contains
    Element defaults (body, a, h1–h6)
    Never
    Class selectors

  4. layout

    Contains
    Page-level scaffolding: shells, grids, regions
    Never
    Component internals

  5. components

    Contains
    Component classes
    Never
    Page-specific overrides

  6. utilities

    Contains
    Single-purpose helpers
    Never
    Multi-declaration rule blocks

  7. overrides

    Contains
    Third-party fixes, documented exceptions
    Never
    New design decisions

Browser profiles

Every task resolves a profile before generating CSS: explicit instruction → project config → default evergreen. Feature tiers come from Baseline dates, and every row is checked against live webstatus.dev data.

View browser-profiles.md ↗
Profile Fallbacks Behavior
modern none Latest engines; ship all Stable features directly, no @supports.
evergreen minimal Auto-updating browsers; @supports reserved for Emerging features.
enterprise progressive Slow-updating fleets; working baseline first, then enhance.
legacy extensive Every non-universal feature needs a working fallback.

Verified, not just documented

Twenty-eight of the rules are enforced by a zero-dependency linter, so they are executable rather than advisory. This site's own stylesheet, and every example inside the skill files, is gated by it on every push. The judgment rules, whether a token is semantic or whether @scope is warranted, stay with css-reviewer: a clean run is a floor, not a pass. A second script checks every Baseline date in the browser profiles against webstatus.dev and lists the next date-driven tier changes.

Field-tested against Chrome's Modern Web Guidance

We compared the skills with Chrome's Modern Web Guidance, verified the disagreements in a browser, and benchmarked both. These are the rules that changed.

Read the gap analysis ↗
Fixed

Reset scope

A * margin reset beats the browser's margin: auto, so modal dialogs and popovers pin to the top-left corner. It also overrides every web component's :host margin. Margins now reset per element, and only box-sizing stays on *.

View the rule ↗
Fixed

Focus rings in forced colors

Forced-colors mode removes box-shadow, so a shadow-only focus ring vanishes in Windows High Contrast. The linter no longer accepts one; keep a transparent outline under the shadow.

View the rule ↗
Measured

100vw, every variant

With a 17px scrollbar, 100vw, 100svw and 100dvw are all wider than the page (Chromium 156), so switching units fixes nothing. Use 100% or a full-bleed grid.

View the rule ↗
New

Web components

Styling across the shadow boundary: :host display, custom-property theming with private aliases, :state(), ::part(), and never :host-context().

View the rule ↗
Benchmark

Four arms, one card

The same refactor task ran with no guidance, with Chrome's skill, with ours, and with both. All four avoided the seven planted traps. Only the arms using css-refactor also made the safe modernizations. The run exposed two refactor gaps, both now fixed.
